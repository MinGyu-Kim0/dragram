# 작업 실행 영역

이 디렉토리는 아직 실행 코드가 없는 후속 구현의 책임 명세다.
현재 API는 동기 처리하며 Celery·Redis·DB Job·예산 예약은 구현되지 않았다.

`jobs`는 DB에 기록하는 작업 수명과 비용을 담당하고, Celery 실행 함수는 각 기능의
`tasks.py`에 둔다. API·worker·Beat는 하나의 backend 코드와 이미지를 공유한다.

| 추가할 파일 | 책임 |
| --- | --- |
| `models.py` | Job, 실행 시도, 실제 호출 기록, 예산 예약 |
| `execution.py` | 선점·기한·시도·취소·조건부 완료·복구 규칙의 단일 기준 |
| `dispatch.py` | 커밋 후 발행, 정해진 작업 종류와 Celery 경로 연결 |
| `budgets.py` | 사용자/공용/전체 예산 예약·정산·불명 비용 보존 |
| `llm.py` | 공통 호출 제한·사용량 기록; 문법별 프롬프트는 해당 기능이 소유 |
| `tasks.py` | Beat가 예약하고 worker가 실행하는 복구 task |

개인 분석은 `analysis`, 공용 설명 생성·승인은 `grammar`가 소유한다.
공통 코드가 생길 때 현재 `analysis/llm.py`에서 필요한 호출 관리 부분만 추출한다.
Redis는 큐, PostgreSQL은 작업 상태·분석 재사용·비용 기록의 기준으로 삼는다.

구현 전 확정할 정책:
- 전체 Job 기한의 의미와 선점·유료 호출 직전·완료 시점의 기한 검사.
- 공용 설명 Job의 시스템 소유·공용 예산과 개인 계정 삭제의 분리.
- 결과 저장과 완료의 원자성, 늦은 시도의 결과 차단, 불명 호출 비용의 보존.

필수 검증은 만료 메시지가 복구 task보다 먼저 소비되는 경우,
공용 작업 요청자가 탈퇴하는 경우, 응답 직후 worker가 중단되는 경우다.
