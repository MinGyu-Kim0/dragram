# 내 일본어를 사용자별 테이블이 아니라 공용 분석의 sense_ids 배열로 계산한다

사용자가 드래그한 문장에 나온 단어·한자·용법(내 일본어)은 본인만 본다. 이를 위해 사용자별 테이블(user_word·user_kanji·user_usage)을 두지 않고, 내 `user_sentence`에서 공용 분석을 따라가 계산한다.

- 단어: `sentence_analysis.sense_ids`(그 문장에서 고른 단어 뜻 ID 목록)를 모은다. 단어는 뜻(`word_sense`)에서 유도한다. 같은 단어라도 문장마다 뜻이 다를 수 있어서(手を取る / 休みを取る) 단어 ID가 아니라 뜻 ID로 둔다.
- 한자: 내 `user_sentence.original_text`에서 글자를 직접 뽑는다(사전형이 아니라 실제로 본 표기).
- 용법: 내 문장들의 `span_match`를 모은다.

칸 하나로 끝나고, 문장을 지우면 자동으로 빠져서 데이터가 따로 놀지 않는다.

## Considered Options

- 사용자별 테이블 3개: 조회와 '본 횟수순' 정렬이 쉽지만, 테이블이 늘고 문장 삭제·패턴 합치기 때마다 맞춰줘야 한다. 무거운 정렬이 필요해지면 그때 추가한다.
- 단어 ID 배열(`word_ids`)과 뜻 순번 배열(`word_senses`): 처음 안이었다. 배열 순번은 JMdict 갱신으로 뜻 순서가 바뀌면 다른 뜻을 가리키게 되어, 고정 ID가 있는 `word_sense` 테이블과 `sense_ids` 하나로 바꿨다(design-decisions §23).

## Consequences

- 배열이라 외래 키 보장이 없다. 단어·뜻을 합치거나 지울 때 `sense_ids` 안의 ID도 갱신해야 한다.
- `sense_ids`에 GIN 인덱스를 둔다.
- 학습 카드(Phase 2)의 제외 상태와 복습 이력은 이 계산 결과와 따로 보관한다. 문장을 지우거나 재분석해도 초기화되지 않는다.
