# 사용자는 처음부터 커스텀 사용자 모델로 둔다

Google 로그인을 넣으면서 사용자를 `AbstractUser`를 물려받은 커스텀 사용자 모델(`google_sub` 추가)로 두고 `AUTH_USER_MODEL`로 지정했다. 같은 사람인지는 이메일이 아니라 바뀌지 않는 `google_sub`로 판단해야 하는데, Django 기본 `auth.User`에는 칼럼을 더할 수 없다. `AUTH_USER_MODEL`은 사용자 테이블을 처음 만들 때만 싸게 바꿀 수 있고, 운영 데이터가 생긴 뒤에는 손으로 데이터를 옮기는 위험한 마이그레이션이 필요하다. 그래서 이미 기본 User를 가리키는 테이블이 있었지만, 배포 전인 지금 로컬 DB를 한 번 초기화하는 비용을 감수했다(#92, 2026-10-23 사용자 결정). `AbstractUser`의 비밀번호 칼럼은 그대로 둔다. `createsuperuser` 관리자가 Django admin에 비밀번호로 들어가고, Google로 가입한 계정은 비밀번호를 쓸 수 없게 둔다.

## Considered Options

- 기본 `auth.User`를 두고 `google_sub`를 담는 연결 테이블을 따로 둔다: DB를 초기화하지 않아도 되지만, 로그인할 때마다 두 테이블을 이어 봐야 하고 schema의 `users`와 어긋난다. 사용자 정보가 늘 때마다 옆 테이블이 생기고, 나중에 커스텀 모델로 옮기는 비용은 지금보다 크다.
